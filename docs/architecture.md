# 架构

```text
主聊天模型
  → JANIMA v8.7 手机 Galgame 纯剧情世界书（保留 FM_DNA/变量体系）
  → 完整自然剧情（不要求主回复同时写 Prompt）
  → 一次后台批量分镜（全文事件账本 + 动作阶段 + 女性门禁 + 跨轮身份 DNA）
  → Prompt 写回各自剧情段落（不渲染插件 UI）
  → 智绘姬原生按钮
  → JANIMA Galgame Turbo 8 步实时工作流
```

## 世界书

v8.7 让主模型专心完成自然剧情，不再同时承担 Prompt JSON、证据包和计数格式。世界书要求把人物、动作施受、结果、状态变化和成人阶段写清；插件等整轮结束后才读取全文。

## 静默插件

插件读取最近 16 条 assistant 消息。最新回复即使完全没有 Prompt 或证据包也会进入检查，不再被提前跳过；即使手机尚未渲染该消息 DOM，也能先在聊天数据中完成分镜。手机滚动时，`IntersectionObserver` 会在旧消息重新进入聊天视口后触发单条重扫，修复智绘姬只处理当前可见消息造成的多轮后漏按钮。

插件先用本地事件账本合并同一持续动作，决定 1–6 个按时间分布的剧情窗口；再通过当前聊天模型的一次 quiet 请求同时生成所有 Prompt。返回项必须逐一匹配窗口编号、插入段落和至少一个本地动作类型；成人阶段还必须精确匹配。任何缺项、重复、动作错位或中文 Prompt 都会整轮拒绝并有限重试。纯男性/空场景会在调用前本地判为 0，并清除旧错 Prompt。

st-chatu8 在创建按钮时捕获 Prompt 到点击闭包，因此插件写回新 Prompt 后会移除空的旧按钮，再让 st-chatu8 重建真实按钮；不会只改表面文字。v8.6 的 `JANIMA_SHOT` 证据修复仍作为兼容路径保留，但默认不再向主生成请求注入同步证据合同。

JANIMA 是 Anima 架构而不是 SD1.5/SDXL UNet，不能直接套用经典 IP-Adapter 工作流。角色连续性由完整逐图 DNA 保持；生成端恢复用户原有 Turbo LoRA，以 8 步实时出图，符合 Galgame 连续游玩的优先级。

## 按钮原位

st-chatu8 2.7.7 会按 Prompt 在原始回复中的字符位置创建 `.st-chatu8-image-button`。v1.10 在完整回复分析后把 Prompt 插回被选剧情段落；插件在写回结束、生成结束和消息重新进入手机视口时唤醒其原生 DOM 重扫。`[Unnamed Persona]`、JSON Patch 数组、未通过门禁或捕获旧载荷的空按钮会被移除；已有生成媒体的历史节点只隐藏，不破坏图片。

## 可选后台 AI 审计

启用后，每轮只发送当前 assistant 回复、已有 Prompt 位置、`IMG_COUNT` 与相关角色 DNA。AI 只能返回删除、替换或在指定段落后插入 Prompt 的 JSON 补丁，不能重写剧情。解析、结构验证全部成功才写回；任何失败均保留原文。
