# 架构

```text
主聊天模型
  → JANIMA v8.6 手机 Galgame 剧情证据世界书（保留 FM_DNA/变量体系）
  → 剧情段落 + JANIMA_SHOT 原文证据包 + 紧随其后的 [English prompt] + IMG_COUNT
  → 静默救援器（原句/动作阶段/女性门禁 + 跨轮身份 DNA，不渲染对话 UI）
  → 智绘姬原生按钮
  → JANIMA Galgame Turbo 8 步实时工作流
```

## 世界书

v8.6 保留事件账本与高潮赢家规则，同时要求主模型在同一次回复中为每张图写出“逐字原文引用 + 在场人物/DNA/服装 + 动作施受结果 + 场景表情构图”的隐藏证据包，随后紧跟 Prompt。插件在方括号闭合时唤醒智绘姬；回复结束后只从该证据包补格式或锁回人物 DNA，不再用本地事件阶段模板猜图，也不默认请求当前聊天模型。

## 静默插件

插件读取最近 16 条含证据的 assistant 消息，解析原文引用、Prompt、段落位置与 `IMG_COUNT`。它会删除旧版残留的 `.janima-rescue-panel`，从不向消息容器追加状态栏、工具栏或第二列。手机滚动时，`IntersectionObserver` 会在旧消息重新进入聊天视口后触发单条重扫，修复智绘姬只处理当前可见消息造成的多轮后漏按钮。

快速路径不会对已经绑定旧点击闭包的按钮做表面改字：st-chatu8 会在创建按钮时捕获 Prompt，事后只改 `data-*` 会造成界面与实际 ComfyUI 载荷不一致。若同轮证据校验需要补全方括号或锁回人物 DNA，插件先删除空的旧按钮，再让 st-chatu8 从规范 Prompt 重建真实按钮。缺少逐字原文证据、纯男/纯场景、动作阶段不符、未来剧情引用和无原文依据的人物/服装变化会直接拒绝；插件不会用通用动作或场景模板猜图。慢速二次模型重排与逐图深度重审默认都关闭。

JANIMA 是 Anima 架构而不是 SD1.5/SDXL UNet，不能直接套用经典 IP-Adapter 工作流。角色连续性由完整逐图 DNA 保持；生成端恢复用户原有 Turbo LoRA，以 8 步实时出图，符合 Galgame 连续游玩的优先级。

## 按钮原位

st-chatu8 2.7.7 会按 Prompt 在原始回复中的字符位置创建 `.st-chatu8-image-button`。v8.6 强制证据包和 Prompt 紧跟所选剧情；插件在流式回复期间、生成结束时和消息重新进入手机视口时唤醒其原生 DOM 重扫。`[Unnamed Persona]`、JSON Patch 数组、未通过证据或捕获旧载荷的空按钮会被移除；已有生成媒体的历史节点只隐藏，不破坏图片。

## 可选后台 AI 审计

启用后，每轮只发送当前 assistant 回复、已有 Prompt 位置、`IMG_COUNT` 与相关角色 DNA。AI 只能返回删除、替换或在指定段落后插入 Prompt 的 JSON 补丁，不能重写剧情。解析、结构验证全部成功才写回；任何失败均保留原文。
